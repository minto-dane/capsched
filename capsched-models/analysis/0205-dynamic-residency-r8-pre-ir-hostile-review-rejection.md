## Activation Blockers

- A staging transaction identity appears after the receipts generated by its
  staging. R8 needs an early `PrepareStagingTxnIdentity` and a later immutable
  `PreparedBundleDescriptor`.
- Connectivity consumption has no preexisting exact input object. R8 needs an
  `ActivationInputCore` bound by certificate, receipt, intent, and context.
- Every receipt must bind attempt, input, intent, context core, staging txn,
  staging generation, boot epoch, CPU incarnation, and prerequisite core.
- Attempt, permit outcome, entry outcome, runtime, and accounting cell
  identities and owners must all exist before their state transitions.
- One constant-size physical `EntryOutcomeCell` must be the only execution
  linearization root. Other bundle objects are immutable inputs or derived
  projections, never part of a variable-size atomic Monitor operation.
- Runtime revocation has one authority. Decision phase is a projection;
  `StopRequested -> StopAcknowledged -> Settled` fences tokens before terminal.
- Prepared expiry/invalidation must terminalize; terminal is forbidden while a
  runtime owner or executable token exists.
- Attempt identity must bind the exact successful allocation reservation/CAS,
  not only a reproducible opportunity/ordinal tuple.

## Failure And Publication Blockers

- A multi-scope transaction needs `EnrollmentSealed` proving exact dependency
  equality before commit.
- Commit outcome and visibility must be one action that rechecks all gates
  Open. Any closing dependency makes authority immediately non-executable.
- A closure prefix slot is terminal only when Aborted or when its committed use
  is fully fenced and settled, not merely when commit won.
- Failure journal writes need root identity and root-generation CAS. Merge
  advances membership generation and invalidates every old fixed-point bit.
- Closure is limited to the canonical component's precharged reverse edges and
  topology. Discovery transfers bounded potential to explicit work and cannot
  increase rank or scan the node population.
- Restart and GC use nonwrapping generations plus a durable checkpoint
  watermark dominating every recoverable cursor.

## Transfer Impossibility Boundary

An executed effect lost before replication is indistinguishable from no effect
to the surviving quorum. No validator can reconstruct that fact. R8 therefore
must select a policy before entry:

```text
LOCAL_ONLY:
  no remote entry fence; source loss permits only ContinuityLost/new incarnation

QUORUM_ENTERED_FENCE:
  exact activation input and entry generation are replicated before the
  physical execution gate opens; a successor never reissues a known-entered
  ordinal
```

Strong continuity requires every predecessor ordinal below `qCut` to have an
exact replicated terminal result and requires predecessor issuance at or above
`qCut` to be impossible. Safe gap may classify a replicated entered-but-
unaccounted ordinal as claim-excluded uncertainty only under a valid external
withdrawal; it never asserts that no physical execution occurred. `LOCAL_ONLY`
cannot claim same-incarnation exactly-once transfer after source loss.

The issuer/placement-owned predecessor decision cell must bind the complete
plan, successor, variant, qCut, evidence, source mint fence, and stop generation
in the same one-use decision. Destination authority starts only after the source
fence and residual upper bound.

## Progress, Scale, And Cost Blockers

- Exact work is represented by compact bounded calendar descriptors that derive
  occurrence IDs, not necessarily stored occurrence arrays.
- External evidence readiness precedes its assigned internal occurrence. A
  missing response is an external countdown result; it does not consume an
  otherwise disabled internal microstep.
- Each opportunity, failure component, transfer, restart, and GC item has a
  separate bounded potential/rank. A global proof may use their finite multiset,
  not one opportunity tuple for unrelated work.
- Recurring logs are `ClosedPrefix + K-bounded live/uncertain suffix`; capacity
  exhaustion backpressures admission or renewal before authority.
- `ProtectionDomainKey`, `ExecutionSubjectKey`, and `SchedContextKey` are
  separate. Active hardware owner is the protected Domain context.
- Static `DomainContextCapsule` receipts are separated from per-cell
  `ContextUseSnapshot`. The hot path is `InstallContext` when generations
  change, O(1) `SpendExecutionCell` on Domain switch, and compare-only
  `ResumeSameDomain`. Ordinary resume cannot require durable writes, log scans,
  remote calls, or full signature verification.
